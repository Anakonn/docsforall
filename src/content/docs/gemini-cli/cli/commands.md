# CLI 명령어

Gemini CLI는 세션 관리, 인터페이스 커스터마이징, 동작 제어를 위한 여러 내장 명령어를 지원합니다. 이 명령어들은 슬래시(`/`), at 기호(`@`), 느낌표(`!`)로 시작합니다.

## 슬래시 명령어 (`/`)

슬래시 명령어는 CLI 자체에 대한 메타 레벨 제어를 제공합니다.

- **`/bug`**
  - **설명:** Gemini CLI에 대한 이슈를 등록합니다. 기본적으로 이슈는 Gemini CLI GitHub 저장소에 등록됩니다. `/bug` 뒤에 입력한 문자열이 버그 제목이 됩니다. 기본 `/bug` 동작은 `.gemini/settings.json` 파일의 `bugCommand` 설정으로 수정할 수 있습니다.

- **`/chat`**
  - **설명:** 대화 상태를 분기하거나 이전 세션에서 상태를 재개하기 위해 대화 히스토리를 저장하고 재개합니다.
  - **하위 명령어:**
    - **`save`**
      - **설명:** 현재 대화 히스토리를 저장합니다. 대화 상태를 식별하기 위한 `<tag>`를 추가해야 합니다.
      - **사용법:** `/chat save <tag>`
    - **`resume`**
      - **설명:** 이전 저장에서 대화를 재개합니다.
      - **사용법:** `/chat resume <tag>`
    - **`list`**
      - **설명:** 대화 상태 재개에 사용 가능한 태그 목록을 표시합니다.

- **`/clear`**
  - **설명:** CLI 내의 가시적인 세션 히스토리와 스크롤백을 포함한 터미널 화면을 지웁니다. 기본 세션 데이터(히스토리 호출용)는 구현에 따라 보존될 수 있지만, 시각적 표시는 지워집니다.
  - **키보드 단축키:** 언제든지 **Ctrl+L**을 눌러 지우기 작업을 수행할 수 있습니다.

- **`/compress`**
  - **설명:** 전체 채팅 컨텍스트를 요약으로 대체합니다. 이는 발생한 내용의 높은 수준 요약을 유지하면서 향후 작업에 사용되는 토큰을 절약합니다.

- **`/editor`**
  - **설명:** 지원되는 편집기를 선택할 수 있는 대화상자를 엽니다.

- **`/help`** (또는 **`/?`**)
  - **설명:** 사용 가능한 명령어와 사용법을 포함한 Gemini CLI에 대한 도움말 정보를 표시합니다.

- **`/mcp`**
  - **설명:** 구성된 Model Context Protocol (MCP) 서버, 연결 상태, 서버 세부사항, 사용 가능한 도구 목록을 표시합니다.
  - **하위 명령어:**
    - **`desc`** 또는 **`descriptions`**:
      - **설명:** MCP 서버와 도구에 대한 자세한 설명을 표시합니다.
    - **`nodesc`** 또는 **`nodescriptions`**:
      - **설명:** 도구 설명을 숨기고 도구 이름만 표시합니다.
    - **`schema`**:
      - **설명:** 도구의 구성된 매개변수에 대한 전체 JSON 스키마를 표시합니다.
  - **키보드 단축키:** 언제든지 **Ctrl+T**를 눌러 도구 설명 표시/숨김을 전환할 수 있습니다.

- **`/memory`**
  - **설명:** AI의 지시 컨텍스트(`GEMINI.md` 파일에서 로드된 계층적 메모리)를 관리합니다.
  - **하위 명령어:**
    - **`add`**:
      - **설명:** AI의 메모리에 다음 텍스트를 추가합니다. 사용법: `/memory add <기억할 텍스트>`
    - **`show`**:
      - **설명:** 모든 `GEMINI.md` 파일에서 로드된 현재 계층적 메모리의 전체 연결된 내용을 표시합니다. 이를 통해 Gemini 모델에 제공되는 지시 컨텍스트를 검사할 수 있습니다.
    - **`refresh`**:
      - **설명:** 구성된 위치(전역, 프로젝트/상위 디렉토리, 하위 디렉토리)에서 발견된 모든 `GEMINI.md` 파일에서 계층적 지시 메모리를 다시 로드합니다. 이 명령어는 최신 `GEMINI.md` 내용으로 모델을 업데이트합니다.
    - **참고:** `GEMINI.md` 파일이 계층적 메모리에 기여하는 방법에 대한 자세한 내용은 [CLI 설정 문서](/gemini-cli/cli/configuration#4-geminimd-files-hierarchical-instructional-context)를 참고하세요.

- **`/restore`**
  - **설명:** 프로젝트 파일을 도구가 실행되기 직전 상태로 복원합니다. 도구가 만든 파일 편집을 취소하는 데 특히 유용합니다. 도구 호출 ID 없이 실행하면 복원할 수 있는 체크포인트 목록이 표시됩니다.
  - **사용법:** `/restore [tool_call_id]`
  - **참고:** CLI가 `--checkpointing` 옵션으로 호출되거나 [설정](/gemini-cli/cli/configuration)을 통해 구성된 경우에만 사용 가능합니다. 자세한 내용은 [체크포인팅 문서](/gemini-cli/checkpointing)를 참고하세요.

- **`/stats`**
  - **설명:** 토큰 사용량, 캐시된 토큰 절약(사용 가능한 경우), 세션 지속 시간을 포함한 현재 Gemini CLI 세션의 자세한 통계를 표시합니다. 참고: 캐시된 토큰 정보는 캐시된 토큰이 사용될 때만 표시되며, 이는 API 키 인증에서 발생하지만 현재 OAuth 인증에서는 발생하지 않습니다.

- [**`/theme`**](/gemini-cli/cli/themes)
  - **설명:** Gemini CLI의 시각적 테마를 변경할 수 있는 대화상자를 엽니다.

- **`/auth`**
  - **설명:** 인증 방법을 변경할 수 있는 대화상자를 엽니다.

- **`/about`**
  - **설명:** 버전 정보를 표시합니다. 이슈 등록 시 이 정보를 공유해 주세요.

- [**`/tools`**](/gemini-cli/tools)
  - **설명:** Gemini CLI 내에서 현재 사용 가능한 도구 목록을 표시합니다.
  - **하위 명령어:**
    - **`desc`** 또는 **`descriptions`**:
      - **설명:** 모델에 제공된 각 도구의 전체 설명과 함께 각 도구의 이름을 포함한 자세한 설명을 표시합니다.
    - **`nodesc`** 또는 **`nodescriptions`**:
      - **설명:** 도구 설명을 숨기고 도구 이름만 표시합니다.

- **`/quit`** (또는 **`/exit`**)
  - **설명:** Gemini CLI를 종료합니다.

## At 명령어 (`@`)

At 명령어는 파일이나 디렉토리의 내용을 Gemini에 대한 프롬프트의 일부로 포함하는 데 사용됩니다. 이 명령어는 git 인식 필터링을 포함합니다.

- **`@<path_to_file_or_directory>`**
  - **설명:** 지정된 파일 또는 파일들의 내용을 현재 프롬프트에 주입합니다. 특정 코드, 텍스트, 파일 모음에 대한 질문을 하는 데 유용합니다.
  - **예시:**
    - `@path/to/your/file.txt 이 텍스트를 설명해줘.`
    - `@src/my_project/ 이 디렉토리의 코드를 요약해줘.`
    - `이 파일은 무엇에 관한 건가요? @README.md`
  - **세부사항:**
    - 단일 파일 경로가 제공되면 해당 파일의 내용을 읽습니다.
    - 디렉토리 경로가 제공되면 해당 디렉토리와 하위 디렉토리 내 파일들의 내용을 읽으려고 시도합니다.
    - 경로의 공백은 백슬래시로 이스케이프해야 합니다(예: `@My\ Documents/file.txt`).
    - 명령어는 내부적으로 `read_many_files` 도구를 사용합니다. 내용이 가져와진 후 Gemini 모델로 전송되기 전에 쿼리에 삽입됩니다.
    - **Git 인식 필터링:** 기본적으로 git-ignored 파일(`node_modules/`, `dist/`, `.env`, `.git/` 등)은 제외됩니다. 이 동작은 `fileFiltering` 설정을 통해 변경할 수 있습니다.
    - **파일 유형:** 명령어는 텍스트 기반 파일을 위한 것입니다. 모든 파일을 읽으려고 시도할 수 있지만, 성능과 관련성을 보장하기 위해 바이너리 파일이나 매우 큰 파일은 기본 `read_many_files` 도구에 의해 건너뛰거나 잘릴 수 있습니다. 도구는 파일이 건너뛰어졌는지 표시합니다.
  - **출력:** CLI는 `read_many_files`가 사용되었음을 나타내는 도구 호출 메시지와 함께 처리된 경로(들)의 상태를 자세히 설명하는 메시지를 표시합니다.

- **`@` (단독 at 기호)**
  - **설명:** 경로 없이 단독 `@` 기호를 입력하면 쿼리가 그대로 Gemini 모델로 전달됩니다. 프롬프트에서 `@` 기호에 대해 구체적으로 이야기할 때 유용할 수 있습니다.

### `@` 명령어의 오류 처리

- `@` 뒤에 지정된 경로를 찾을 수 없거나 유효하지 않은 경우 오류 메시지가 표시되고, 쿼리가 Gemini 모델로 전송되지 않거나 파일 내용 없이 전송될 수 있습니다.
- `read_many_files` 도구에서 오류(예: 권한 문제)가 발생하면 이도 보고됩니다.

## 셸 모드 및 통과 명령어 (`!`)

`!` 접두사는 Gemini CLI 내에서 직접 시스템 셸과 상호작용할 수 있게 합니다.

- **`!<shell_command>`**
  - **설명:** 시스템의 기본 셸에서 주어진 `<shell_command>`를 실행합니다. 명령어의 모든 출력이나 오류가 터미널에 표시됩니다.
  - **예시:**
    - `!ls -la` (`ls -la`를 실행하고 Gemini CLI로 돌아옴)
    - `!git status` (`git status`를 실행하고 Gemini CLI로 돌아옴)

- **`!` (셸 모드 전환)**
  - **설명:** 단독으로 `!`를 입력하면 셸 모드가 전환됩니다.
    - **셸 모드 진입:**
      - 활성화되면 셸 모드는 다른 색상과 "Shell Mode Indicator"를 사용합니다.
      - 셸 모드에서는 입력한 텍스트가 직접 셸 명령어로 해석됩니다.
    - **셸 모드 종료:**
      - 종료되면 UI가 표준 모양으로 되돌아가고 일반 Gemini CLI 동작이 재개됩니다.

- **모든 `!` 사용에 대한 주의사항:** 셸 모드에서 실행하는 명령어는 터미널에서 직접 실행하는 것과 동일한 권한과 영향을 가집니다.
