# 체크포인팅

Gemini CLI는 AI 기반 도구에 의해 파일 수정이 이루어지기 전에 프로젝트 상태의 스냅샷을 자동으로 저장하는 체크포인팅 기능을 포함합니다. 이를 통해 코드 변경사항을 안전하게 실험하고 적용할 수 있으며, 도구가 실행되기 전 상태로 즉시 되돌릴 수 있다는 것을 알 수 있습니다.

## 작동 방식

파일 시스템을 수정하는 도구(예: `write_file` 또는 `replace`)를 승인하면 CLI가 자동으로 "체크포인트"를 생성합니다. 이 체크포인트는 다음을 포함합니다:

1. **Git 스냅샷:** 홈 디렉토리(`~/.gemini/history/<project_hash>`)에 위치한 특별한 섀도우 Git 저장소에서 커밋이 생성됩니다. 이 스냅샷은 해당 순간의 프로젝트 파일들의 완전한 상태를 캡처합니다. 이는 사용자 자신의 프로젝트 Git 저장소에 **간섭하지 않습니다**.
2. **대화 히스토리:** 에이전트와 나눈 전체 대화가 저장됩니다.
3. **도구 호출:** 실행되려던 특정 도구 호출도 저장됩니다.

변경사항을 취소하거나 단순히 되돌리고 싶다면 `/restore` 명령어를 사용할 수 있습니다. 체크포인트를 복원하면:

- 프로젝트의 모든 파일이 스냅샷에 캡처된 상태로 되돌아갑니다.
- CLI에서 대화 히스토리가 복원됩니다.
- 원래 도구 호출이 다시 제안되어 다시 실행하거나, 수정하거나, 단순히 무시할 수 있습니다.

체크포인트 데이터는 모두 로컬 머신에 저장됩니다. Git 스냅샷은 섀도우 저장소에 저장되고, 대화 히스토리와 도구 호출은 프로젝트의 임시 디렉토리(일반적으로 `~/.gemini/tmp/<project_hash>/checkpoints`)에 있는 JSON 파일에 저장됩니다.

## 기능 활성화

체크포인팅 기능은 기본적으로 비활성화되어 있습니다. 명령줄 플래그를 사용하거나 `settings.json` 파일을 편집하여 활성화할 수 있습니다.

### 명령줄 플래그 사용

Gemini CLI를 시작할 때 `--checkpointing` 플래그를 사용하여 현재 세션에 대해 체크포인팅을 활성화할 수 있습니다:

```bash
gemini --checkpointing
```

### `settings.json` 파일 사용

모든 세션에 대해 기본적으로 체크포인팅을 활성화하려면 `settings.json` 파일을 편집해야 합니다.

`settings.json`에 다음 키를 추가하세요:

```json
{
  "checkpointing": {
    "enabled": true
  }
}
```

## `/restore` 명령어 사용

활성화되면 체크포인트가 자동으로 생성됩니다. 이를 관리하려면 `/restore` 명령어를 사용합니다.

### 사용 가능한 체크포인트 목록 보기

현재 프로젝트에 대한 모든 저장된 체크포인트 목록을 보려면 다음을 실행하세요:

```
/restore
```

CLI는 사용 가능한 체크포인트 파일 목록을 표시합니다. 이 파일 이름들은 일반적으로 타임스탬프, 수정되는 파일 이름, 실행되려던 도구 이름으로 구성됩니다(예: `2025-06-22T10-00-00_000Z-my-file.txt-write_file`).

### 특정 체크포인트 복원

프로젝트를 특정 체크포인트로 복원하려면 목록에서 체크포인트 파일을 사용하세요:

```
/restore <checkpoint_file>
```

예시:

```
/restore 2025-06-22T10-00-00_000Z-my-file.txt-write_file
```

명령어를 실행한 후, 파일과 대화가 체크포인트가 생성되었을 때의 상태로 즉시 복원되고, 원래 도구 프롬프트가 다시 나타납니다.
